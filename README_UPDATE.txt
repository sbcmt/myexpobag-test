【利用方法】
1. GitHub Pages反映後、管理ページの「☰ メニュー」→「登録商品一覧・簡易編集」を開く。
2. 商品名・商品ID・カテゴリ・表示状態で絞り込む。
3. 単品商品は通常価格、キャンペーン価格、通常/予約在庫を直接変更する。
4. バリエーション商品は行を展開し、バリエーション別の価格、在庫を変更する。
   子価格の空欄は親価格に追従。通常在庫と予約在庫は予約設定に応じて切替。
5. 「この商品の変更を保存」で、管理用の下書き商品のみ保存される。
6. 管理者が「公開操作の画面へ」から「お客様ページに反映」を押して公開する。
   ※在庫も公開操作まで購入者向け在庫に反映しない。
7. ブランド設定で色を選んで保存後、管理画面の「商品QRダウンロード」→「プレビュー」を開く。
   「アクセント」を選ぶとブランドカラーが装飾色に使われる。
   「ホワイト」は従来どおり白地のレイアウト。

【安全設計】
・同じ商品を別画面または注文処理が更新していた場合、保存を拒否して再読込を促す。
・一括上書きせず、変更したフィールドだけをFirestoreトランザクションで更新。
・既存のFirestoreルールを変更する必要はない（既存商品update許可内）。
・本番用Firebase接続設定やPOP等のassetsには変更なし。
・管理画面の既存アイコン、テキストロゴ、6タブ、予約設定、CSV設定は維持。
・購入者側のアイコン/ファビコンを新規追加しない。
・Free/Pro判定とStripe連携はこの更新には含まない。現段階のテストは両カードスタイル表示可。

【動作確認】
・Chromium／擬似Firestoreで単品商品・2軸SKU・通常/予約在庫・価格の保存を検証。
・注文を模した在庫の競合による保存拒否を検証。
・ブランド色（ピーチミルク）とホワイトを検証。
・Firebaseテスト環境での最終動作確認はGitHub Pages反映後に行う。
